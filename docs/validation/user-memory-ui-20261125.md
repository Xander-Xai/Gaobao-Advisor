# Explicit user memory in normal chat

The right panel now connects a separately issued memory vault, explicitly edits/deletes bounded preferences and can erase the live vault. It uses the existing authenticated memory API and passes X-User-Memory-Token only on opted-in text chat. The credential remains in page memory; refresh/unmount disconnects, and users can reconnect with their privately saved credential. It is not persisted in browser storage or chat session state. No automatic extraction or production enablement. Backend development-only restriction remains pending identity, privacy and retention review. A real-client streaming regression checks header attachment across unrelated sessions and removal after disconnect. Actual model personalization quality and full browser/backend E2E remain unverified.
