# MySQL 8.4 admissions-history query index validation — 2026-11-27

## Scope and test environment

- Checkout: `8b636dbc76c35f85714cb3f6d74294eb9f9a2737` before the index change.
- MySQL Community Server 8.4.13, Docker container, WSL2 Linux 6.6.87.2.
- Python 3.12.13 / SQLAlchemy 2.0.50; host Intel i5-14600KF, 20 logical CPUs,
  approximately 16 GiB RAM.
- Isolated database `gaobao_benchmark`; all rows generated by the existing
  benchmark fixture plus synthetic school-level rows. No real admissions data.
- `admission_scores`: 110,000 rows; `schools`: 2,000 rows. Test filter selected
  500 schools and 1,250 school-level score rows before rank sorting.
- One connection, five warmups and 30 measured samples. This is SQL-level
  elapsed time, not HTTP latency or a production SLO.

## Query

The query shape matches `server/services/industrial_admissions.py::query_history`
(the join and selected columns are kept explicit for the SQL plan):

```sql
SELECT a.id, s.name
FROM admission_scores AS a
JOIN schools AS s ON s.id = a.school_id
WHERE a.province = :province
  AND a.year = :year
  AND a.subject_type = :subject
  AND a.major_id IS NULL
  AND a.min_rank BETWEEN :lo AND :hi
  AND a.min_score BETWEEN 0 AND 750
  AND a.batch IS NOT NULL
ORDER BY ABS(a.min_rank - :target), a.id
LIMIT 10;
```

Parameters: `province='示例省·甲'`, `year=2024`, `subject='物理类'`,
`lo=2500`, `hi=7500`, `target=5000`.

## Before / after evidence

| State | p50 | p95 | single-connection throughput | Actual plan |
|---|---:|---:|---:|---|
| Before | 15.267 ms | 17.630 ms | 64.47 queries/s | Schools-first plan; 2,000 secondary-index probes into `uq_admission_score`, filtering 1,250 matching school rows, then top-N sort. |
| Candidate index present | 4.838 ms | 8.272 ms | 185.09 queries/s | Range scan on `ix_adm_history_scope_rank`; 1,250 rows filtered/sorted, then 10 PK lookups into `schools`. |

The candidate was created only in the disposable benchmark schema, measured,
then dropped. `EXPLAIN ANALYZE` selected the index and reduced the observed
execution-time interval from approximately 17.1 ms to 4.52 ms for this query.
The sort for `ABS(...)` remains; the index does not claim to eliminate it.

## Decision and limits

Adopted as `ix_adm_history_scope_rank (province, year, subject_type, major_id,
min_rank)` in Alembic revision `20261127_0010`. Equality predicates lead; the
range column follows. A migration regression checks the exact index definition
and preserves a row inserted at prior head `20261125_0009`.

This benchmark is synthetic and only establishes this test plan's response to
the additive index. It does not establish real dataset selectivity or write
overhead under production traffic. Monitor index size/write cost and repeat the
same comparison against the authorized target dataset before release. Other
workloads (plans, ranks, sessions, jobs, deeper admin pagination) retain their
existing indexes/benchmarks and have not been re-optimized by this change.
