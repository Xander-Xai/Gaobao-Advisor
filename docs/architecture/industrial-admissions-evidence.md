### 工业会话并发与删除边界（2026-11-25）

工业 SSE 在准备图前读取 MySQL 会话行、原始 slots JSON 与最新消息 ID，形成服务端版本；最终原子持久化前重新锁定同一行并比对版本。仅服务端生成的新匿名会话允许插入；旧 bearer 对应会话不存在即拒绝，旧在途任务不得重建被删除行。同版本并发提交仅允许首个成功，其余拒绝，不自动重放。删除在子表清理前锁定会话行。旧 profile PUT/next-question/skip、feedback/highlight 写入口工业模式暂时返回 503；语音/报告已有独立发布限制，开发模式保持兼容。新匿名安全拒绝不签发尚未持久化的 session token。此方案不是请求幂等或完整账户/token 吊销：已提交的流式响应仍可能在删除后抵达，无法撤回已发送内容；匿名重试可能创建不同会话，提交结果未知需要独立幂等合同。旧数据和离线工具、其他进程、备份、外部 provider、生产隐私及真实 MySQL 多副本竞态仍需验收。新增 SQLite 逻辑回归不证明 MySQL 行锁并发语义。

### 查询事实指纹与真实数据库竞态回归（2026-11-25）

工业历史查询将规范化 JSON（年度、省份、科类、分数、累计位次、行 ID、院校 ID、院校名、批次、最低分、最低位次）计算 SHA-256，最终渲染重新计算并要求与当前审批年度一致；变动或缺失拒答。文本及结构化卡片共享指纹，文本随已交付回答入库；不再公开内部授权标识。指纹只是本次查询值的完整性标识，不是签名、源文件哈希、不可变全库版本或官方真实性证明，无法单凭它还原历史数据；数据集清单、官方行级来源和审批链仍需建立。新增真实 MySQL 同版本竞争与删除/在途写竞争回归，接入既有 MySQL + Redis CI 的 test_admin_mysql.py；使用合成记录，不能代替真实业务和多副本压测。

### 已认证续轮请求幂等（独立候选 PR，2026-11-25）

工业 POST /api/v1/chat 可选 Idempotency-Key（16–128 ASCII 字母数字、下划线、连字符），仅有效 session bearer 且无跨任务记忆凭证。调用方必须重试相同 key、scene、message、slots；同会话同键异请求 SSE error IDEMPOTENCY_CONFLICT（无 done），不重算已完成的请求。新表 chat_turn_receipts（唯一迁移 20261125_0009）按 conversation PK + key SHA-256 主键绑定请求摘要与已交付文本、结构化卡片、槽位、稳定消息 ID；与消息/槽位同一事务提交。重复并发允许重复准备图，但只允许一个 durable 写入，失败者可查回执。已提交回执与会话同生命周期，删除显式清除；备份、保留政策、已取出响应和真实隐私验收仍有边界。重放是原轮历史快照而非当前 profile，不能在后续轮次之后用其旧槽位覆盖最新状态。无 key 保持旧契约，匿名首轮不支持 keyed retry；前端 API 可传 idempotencyKey，未实现 UI 自动重试。安全拒绝不写回执，不签发成功 done。此实现不承诺 exactly-once 执行、无穷期重放或客户端持久化 key；同 key 未提交失败仍可重试。新迁移和真实 MySQL 回归必须通过 exact-head CI 才可合并。
